# Справочник городов: статистика CSV/XML

Консольное Java-приложение для анализа справочника городов. Программа читает файл в формате CSV или XML и строит сводную статистику:

- дублирующиеся записи с количеством повторений;
- количество 1-, 2-, 3-, 4- и 5-этажных зданий по каждому городу;
- время обработки файла;
- количество пропущенных невалидных строк.

После вывода статистики приложение снова ожидает путь к файлу. Выход — только по команде пользователя.

## Возможности

- Поддержка двух форматов: CSV и XML.
- Общий контракт парсеров — формат можно заменить без изменения остальной логики.
- Потоковое чтение: файл не загружается в память целиком.
- Обработка ошибок без падения: неверный путь и неизвестный формат не завершают программу; невалидные строки и записи пропускаются и подсчитываются.
- Подсчёт статистики через `HashMap`, без полного перебора записей на каждом шаге.
- Разделение ответственности: модель, парсеры, статистика и консольный интерфейс — отдельные компоненты.

## Требования

- JDK 21 или новее.
- Внешние библиотеки не нужны: используются только стандартные средства JDK, включая StAX для XML.

## Сборка и запуск

Из корня проекта:

```bash
mkdir -p out
javac -encoding UTF-8 -d out $(find src -name '*.java')
java -cp out Main
```

Если в проекте есть `build.sh`, сборка выполняется так:

```bash
bash build.sh
java -cp out Main
```

## Использование

После запуска появляется приглашение:

```text
Введите путь к CSV/XML (exit — выход):
```

Введите путь к файлу, например:

```text
correct.csv
```

или:

```text
correct.xml
```

Команды выхода:

- `exit`
- `quit`
- `q`
- `Ctrl+D`

Пустая строка просто повторяет приглашение. После ошибки или вывода статистики программа продолжает работу.

## Пример вывода

```text
Дубликаты:
2x Барнаул | Дальняя улица | 56 | 2

Здания по этажам:
Барнаул: 1-эт = 0 | 2-эт = 2 | 3-эт = 0 | 4-эт = 0 | 5-эт = 0 |
Братск: 1-эт = 0 | 2-эт = 0 | 3-эт = 0 | 4-эт = 0 | 5-эт = 1 |
Тест: 1-эт = 1 | 2-эт = 0 | 3-эт = 0 | 4-эт = 0 | 5-эт = 0 |
Тест;город: 1-эт = 0 | 2-эт = 0 | 3-эт = 1 | 4-эт = 0 | 5-эт = 0 |

Время обработки: 12 мс

Пропущено строк при обработке: 0
```

Дубликатом считается запись, у которой совпадают все поля: город, улица, дом и этаж.

## Форматы файлов

### CSV

Разделитель — `;`. Первая строка — заголовок. Поля могут быть в кавычках, внутри кавычек поддерживается экранирование `""`.

```csv
"city";"street";"house";"floor"
"Барнаул";"Дальняя улица";"56";2
"Братск";"Большая Октябрьская улица";65;5
```

### XML

Корневой элемент — `<root>`, каждая запись — `<item>` с атрибутами `city`, `street`, `house`, `floor`.

```xml
<?xml version="1.0" encoding="UTF-8"?>
<root>
    <item city="Барнаул" street="Дальняя улица" house="56" floor="2" />
    <item city="Братск" street="Большая Октябрьская улица" house="65" floor="5" />
</root>
```

## Структура проекта

```text
src/
├── Main.java
├── parser/
│   ├── CityRecord.java          # модель одной записи справочника
│   ├── DirectoryParser.java     # общий интерфейс парсеров
│   ├── CSVParser.java           # потоковый разбор CSV
│   ├── XMLParser.java           # потоковый разбор XML через StAX
│   └── ParserFactory.java       # выбор парсера по расширению файла
├── stats/
│   ├── Statistics.java          # результат статистики
│   ├── StatisticsCollector.java # накопление дубликатов и этажности
│   └── StatisticsServies.java   # запуск парсинга и замер времени
└── ui/
    └── ConsoleUI.java           # цикл ввода-вывода и обработка ошибок
```

## Как это работает

1. `ParserFactory` выбирает парсер по расширению файла.
2. `CSVParser` или `XMLParser` читает файл потоково, пропускает невалидные строки/записи и передаёт каждую `CityRecord` в `StatisticsCollector`.
3. Коллектор считает повторы записей и количество зданий по этажам для каждого города.
4. `StatisticsServies` замеряет время обработки и передаёт в статистику число пропущенных записей.
5. `ConsoleUI` печатает статистику, включая количество пропусков, и снова запрашивает путь.

## Тестовые данные

В репозитории есть файлы:

- `correct.csv`, `correct.xml` — корректные данные для проверки статистики;
- `test.csv`, `test.xml` — набор стандартных и нестандартных ситуаций: дубликаты, `;` внутри кавычек, экранированные кавычки, пустые значения, лишние и недостающие поля/атрибуты, нечисловой этаж.

Некоторые файлы из `test.*` специально содержат ошибки. Невалидные строки CSV и записи XML не прерывают обработку: они пропускаются, а их количество выводится в статистике. На `test.csv` пропускаются 2 строки, на `test.xml` — 5 записей. Битый XML или ошибка чтения файла выводятся как сообщение об ошибке, после чего приложение продолжает работу.

## Обработка ошибок

Все операции с файлами и вводом пользователя обёрнуты в обработку исключений:

- файл не найден;
- неподдерживаемое расширение;
- ошибка чтения CSV/XML;
- неверный этаж;
- некорректное количество полей или отсутствующие атрибуты.

Невалидная запись (неверный этаж, недостаточное количество полей, отсутствующие атрибуты) не прерывает обработку файла: она пропускается, а её количество выводится в статистике. Ошибка чтения файла или синтаксиса XML прерывает обработку текущего файла: сообщение выводится в консоль, после чего приложение снова просит путь. Выход возможен только по команде завершения.
